**Правила и геймплей — в [`GAME_MANIFEST.md`](GAME_MANIFEST.md), схемы — в [`DATA_SCHEMAS.md`](DATA_SCHEMAS.md).**
План не отменяет манифест: если план расходится с манифестом, правится план.

**Статус:** v0.39 (2026-10-26). Обновлять при закрытии и добавлении пунктов.

## 0. Как пользоваться

- **Вопрос «что делать дальше»** — открыть этот файл, взять первый блок в разделе «Ближайший шаг», а не гадать по журналу.
- Отметки: `[ ]` — не сделано, `[~]` — в работе, `[x]` — сделано (с датой в скобках).
- Сделанное **не удалять**: строка с `[x]` остаётся историей работ. Устаревший пункт помечается `[x] (отменено)` с причиной.
- Новые задачи — в свой блок; новый блок — в конец раздела 3 с пометкой зависимостей.
- Пункт считается закрытым, только когда выполнены его критерии готовности и правила `AGENTS.md` §2 (тесты — в том же изменении).
- Закрытие пункта сопровождается строкой в `.agents/journal.md` и, если менялось правило, правкой манифеста.
- `❓` в разделе 4 — блокеры: задачи, которые от них зависят, не начинаются без ответа пользователя.

## 1. Где мы сейчас (снимок 2026-10-25)

- **Играбельная петля:** меню → новая игра → переходы между 6 локациями → экран персонажа (инвентарь, экипировка, drag\&drop) → сохранение/загрузка. Петля обрывается на бое: объектов на вылазке, лута, тайников и торговли в UI уже есть, экрана боя нет.
- **UI на префабах:** пилот — экран старта игры. Разметка в `Assets/Prefabs/Screens/NewGameScreen.prefab` (ник с кубиком, наборы из данных двумя колонками, настройки из общей строки-заготовки, набор экипировки в собственной прокрутке), код только связывает данные и считает высоту динамической сетки; ширина, высота, отступы и зазор задаются `LayoutGroup`/`LayoutElement` в инспекторе. Фон элемента — `Image`/спрайт в префабе, задник экрана дополнительно берёт id из `SpriteCatalog`. Остальные экраны пока строятся кодом.
- **Умный маршрут (2026-10-25):** маршрут — сеть звеньев от хаба. Подтипы `path`/`building`/`terrain` (+ `hub`), роль содержания (`highway`, `forest`, `residential`, `laboratory`…), переходы таблицей `route.transitions` в `topology.json`, длина звена и ветки из `chainLength`/`chainWeights`, ветки по правилу нечётных/чётных звеньев, возврат в хаб только с пути за `hubReturn × routeStep`, достройка окном `lookaheadEdges`. Сейв v15, данные: 11 локаций.
- **Готово в Core:** загрузка/валидация данных, предметы, инвентарь, экипировка, артефакты, износ, бой (формула из данных, меткость, патроны, зоны, ОД, ходы, сценарии первого хода «засада»/«сюжет»/«обычный», результат боя — опыт, смерть с респавном, контракт лута, побег из боя с атакой противника и исчезновением противника на локации), магазины оружия (стартовое оружие заряжено, торговый запас разряжен; зарядка, разрядка, перезарядка из самых маленьких стопок, зарядка перетаскиванием), торговцы NPC (данные `Actor.type=trader`, привязка к хабу, ассортимент с условиями, запас с пополнением, покупка и продажа, сейв запаса), повторяемые квесты торговцев (4 случайных предложения, 4 типа целей, принятие/отмена, прогресс, сдача, откат), дерево талантов (ветки row/column, карточки-картинки, подсказки с задержкой, ранги, пороги по вложенным очкам, эффекты в данных), мир (топология, генерация по seed), правила, новая игра, сессия, сейвы v12, смерть (полная потеря инвентаря, независимая страховка надетых вещей, пермасмерть из настроек старта, потеря доли опыта текущего уровня, `IDeathService`, респавн в последнем хабе, `ICombatOutcomeService`), левелинг (перенос излишка опыта, награды с пятого уровня, подтягивание старых сейвов).
- **Проверено (2026-10-25, вечер):** `dotnet` 674/674, сборка без ошибок и предупреждений; Unity EditMode 1/1 и PlayMode 82/82 в batch-mode вне песочницы (78 прежних + 4 новых PlayMode-теста объекта локации, блок A).
