# AnomalyPath — план проекта

Рабочий план: что сделано, что делаем сейчас и что дальше. Версионируется вместе с `docs/`.
**Правила и геймплей — в [`GAME_MANIFEST.md`](GAME_MANIFEST.md), схемы — в [`DATA_SCHEMAS.md`](DATA_SCHEMAS.md).**
План не отменяет манифест: если план расходится с манифестом, правится план.

**Статус:** v0.2 (2026-10-23). Обновлять при закрытии и добавлении пунктов.

---

## 0. Как пользоваться

- **Вопрос «что делать дальше»** — открыть этот файл, взять первый блок в разделе «Ближайший шаг», а не гадать по журналу.
- Отметки: `[ ]` — не сделано, `[~]` — в работе, `[x]` — сделано (с датой в скобках).
- Сделанное **не удалять**: строка с `[x]` остаётся историей работ. Устаревший пункт помечается `[x] (отменено)` с причиной.
- Новые задачи — в свой блок; новый блок — в конец раздела 3 с пометкой зависимостей.
- Пункт считается закрытым, только когда выполнены его критерии готовности и правила `AGENTS.md` §2 (тесты — в том же изменении).
- Закрытие пункта сопровождается строкой в `.agents/journal.md` и, если менялось правило, правкой манифеста.
- `❓` в разделе 4 — блокеры: задачи, которые от них зависят, не начинаются без ответа пользователя.

## 1. Где мы сейчас (снимок 2026-10-23)

- **Играбельная петля:** меню → новая игра → переходы между 6 локациями → экран персонажа (инвентарь, экипировка, drag\&drop) → сохранение/загрузка. Петля обрывается на локациях: объектов, боя, лута и торговли в UI нет.
- **Готово в Core:** загрузка/валидация данных, предметы, инвентарь, экипировка, артефакты, износ, бой (формула из данных, меткость, патроны, зоны, ОД, ходы), мир (топология, генерация по seed), правила, новая игра, сессия, сейвы v3.
- **Проверено (2026-10-23):** `dotnet` 345/345; Unity EditMode 1 тест-кейс (345 проверок, `Logs/EditMode-run.xml`); PlayMode 38/38 (`Logs/PlayMode-run.xml`); рабочее дерево — около 50 файлов не закоммичено.
- **Не сделано:** объекты/спавн/лут, экран боя, смерть и потеря лута, торговля/крафт/ремонт, квесты/фракции/репутация/прокачка, потребности и сон, моды, актуальный билд.
- **Стек и окружение:** см. `.agents/STATE.md` (Unity 6000.6.6f1, URP 17.6, uGUI, Windows).

### A. Вылазка: объекты, спавн, лут  ← следующий блок

Цель: на каждой локации появляется не больше одного объекта, его можно осмотреть и забрать лут — вылазка перестаёт быть «переход с картинкой».

- [x] Ответ на ❓1 (2026-10-23); правило про один объект и уникальные объекты — в манифест §5, v0.91
- [ ] Схемы: `SpawnEntry` и `LootTable` в `docs/DATA_SCHEMAS.md` (§13–14): `objectCount` — 0/1, `SpawnEntry.unique`, правила валидации в §19
- [ ] Данные: 8–12 объектов под 6 локаций (дорога, дом, аномалия, лес), 3–5 таблиц лута, коллекции `col_*`, подключение в `catalog.json`
- [ ] Core: выбор одного объекта на локацию `(template, seed)` — фильтр `requiresTags`/`excludesTags`/`minTier`/`maxTier`, взвешенный выбор, уникальные (`unique`) только по событию или на уникальной локации; детерминизм
- [ ] Core: выдача лута по таблице (детерминированный бросок, стаки, переполнение инвентаря в `Overflow`)
- [ ] Сейв: объекты и забранный лут в состоянии локации (или регенерация по seed — зафиксировать решение в манифесте)
- [ ] Валидатор: новые виды сущностей + ссылки `lootTable`/`actorId`/`eventId`
- [ ] UI: `PlayScreen` — единственный объект локации, «Осмотреть»/«Забрать», подсказка, скрытие использованного, тост
- [ ] Тексты: `strings.{ru,en}.json`, ключи в `UiTextKey`
- [ ] Тесты: новая категория `SpawnTests` (теги, тир, вес, пустой пул, уникальные не выпадают случайно, детерминизм) и `LootTests` (пустая таблица, переполнение, стаки, round-trip)
- [ ] Тесты форматов: `JsonFormatTests`/`FileFormatTests` — строки на новые виды сущностей
