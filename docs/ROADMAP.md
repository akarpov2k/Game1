# AnomalyPath — план проекта

Рабочий план: что сделано, что делаем сейчас и что дальше. Версионируется вместе с `docs/`.
**Правила и геймплей — в [`GAME_MANIFEST.md`](GAME_MANIFEST.md), схемы — в [`DATA_SCHEMAS.md`](DATA_SCHEMAS.md).**
План не отменяет манифест: если план расходится с манифестом, правится план.

**Статус:** v0.21 (2026-10-24). Обновлять при закрытии и добавлении пунктов.

---

## 0. Как пользоваться

- **Вопрос «что делать дальше»** — открыть этот файл, взять первый блок в разделе «Ближайший шаг», а не гадать по журналу.
- Отметки: `[ ]` — не сделано, `[~]` — в работе, `[x]` — сделано (с датой в скобках).
- Сделанное **не удалять**: строка с `[x]` остаётся историей работ. Устаревший пункт помечается `[x] (отменено)` с причиной.
- Новые задачи — в свой блок; новый блок — в конец раздела 3 с пометкой зависимостей.
- Пункт считается закрытым, только когда выполнены его критерии готовности и правила `AGENTS.md` §2 (тесты — в том же изменении).
- Закрытие пункта сопровождается строкой в `.agents/journal.md` и, если менялось правило, правкой манифеста.
- `❓` в разделе 4 — блокеры: задачи, которые от них зависят, не начинаются без ответа пользователя.

## 1. Где мы сейчас (снимок 2026-10-24)

- **Играбельная петля:** меню → новая игра → переходы между 6 локациями → экран персонажа (инвентарь, экипировка, drag\&drop) → сохранение/загрузка. Петля обрывается на локациях: объектов, боя, лута и торговли в UI нет.
- **UI на префабах:** пилот — экран старта игры. Разметка в `Assets/Prefabs/Screens/NewGameScreen.prefab` (ник с кубиком, наборы из данных двумя колонками, настройки из общей строки-заготовки, набор экипировки в собственной прокрутке), код только связывает данные и считает высоту динамической сетки; ширина, высота, отступы и зазор задаются `LayoutGroup`/`LayoutElement` в инспекторе. Фон элемента — `Image`/спрайт в префабе, задник экрана дополнительно берёт id из `SpriteCatalog`. Остальные экраны пока строятся кодом.
- **Готово в Core:** загрузка/валидация данных, предметы, инвентарь, экипировка, артефакты, износ, бой (формула из данных, меткость, патроны, зоны, ОД, ходы, сценарии первого хода «засада»/«сюжет»/«обычный», результат боя — опыт, смерть с респавном, контракт лута), магазины оружия (стартовое оружие заряжено, торговый запас разряжен; зарядка, разрядка, перезарядка из самых маленьких стопок, зарядка перетаскиванием), торговцы NPC (данные `Actor.type=trader`, привязка к хабу, ассортимент с условиями, запас с пополнением, покупка и продажа, сейв запаса), повторяемые квесты торговцев (4 случайных предложения, 4 типа целей, принятие/отмена, прогресс, сдача, откат), дерево талантов (ветки row/column, карточки-картинки, подсказки с задержкой, ранги, пороги по вложенным очкам, эффекты в данных), мир (топология, генерация по seed), правила, новая игра, сессия, сейвы v9, смерть (полная потеря инвентаря, независимая страховка надетых вещей, пермасмерть из настроек старта, `IDeathService`, респавн в последнем хабе, `ICombatOutcomeService`).
- **Проверено (2026-10-24):** `dotnet` 475/475; Unity EditMode/PlayMode после правок результата боя не перезапускались (batch-mode в песочнице упирается в UPM IPC и лицензию — нужен запуск вне песочницы); Unity-сборки не пересобирались, runtime-код использует `ICombatOutcomeService` через DI; рабочее дерево — около 80 файлов не закоммичено.
- **Не сделано:** объекты/спавн/лут, экран боя, UI результата боя и диалог лута, ремонт/крафт, сюжетные квесты, фракции/репутация, левелинг и выдача очков талантов за уровни, потребности и сон, моды, актуальный билд.
- **Стек и окружение:** см. `.agents/STATE.md` (Unity 6000.6.6f1, URP 17.6, uGUI, Windows).
